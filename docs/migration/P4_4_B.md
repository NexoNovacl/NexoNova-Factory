## Implementación en validación

Better Auth 1.7.5 exacto, Prisma/client/adapter-pg 7.5.0, PostgreSQL 16.15,
Node22.23.2, Next15.5.25, React19.2.8, TypeScript5.9.3.
Lockfile propio; hashing mediante `better-auth/crypto`. Sin hashing propio.
Schema auth en app: User, Session, Account, Verification; role enum admin/member.
No TechnicalSmoke ni InternalRequest en el schema auth.

Migración estable `00000000000000_auth_initial`. Prisma diff añadió CREATE SCHEMA
public en el primer intento: fue rechazado con 42501. Se corrigió el schema explícito
app y se excluyó CREATE SCHEMA del SQL revisado, porque el runner ya provisiona app
con owner bpmigrator. **No se ampliaron privilegios del migrador.**
El historial se aplica mediante migrate deploy, nunca db push/reset.

Runtime: SELECT User/Account, CRUD Session, USAGE app; sin DDL ni acceso Verification.
Bootstrap: conexión bpbootstrap separada, SELECT/INSERT User/Account, transacción con
advisory lock; sin endpoint HTTP, contraseña default ni mutación de cuentas existentes.
La fixture de member es exclusivamente de validación offline y no está importada por app.

Sesión: expiresIn=28800, hook público que acota expiresAt a createdAt+8h,
disableSessionRefresh y cookieCache deshabilitada. Wrapper fuerza rememberMe=false.
Cookies host-only/HttpOnly/SameSite=Lax; Secure obligatorio en perfil production.
Perfil local-test solo permite HTTP en 127.0.0.1. Telemetría deshabilitada.
Rate limit adicional conservador global del proceso: cinco intentos de login/minuto;
no depende de X-Forwarded-For. Memoria no compartida, reinicio borra contadores.

## Rutas y ejecución

/login, /auth-check, /admin-check y probes API. Better Auth solo recibe
POST sign-in/email, POST sign-out y GET get-session; signup y edición de usuario
se rechazan antes de delegar. Decisiones de sesión/rol en servidor, sin cache autoritativa.
Respuestas HTTP públicas auth omiten tokens/hashes; APIs privadas no-store.

Se resolvió el build de imports ESM .js→fuentes .ts con extensionAlias en la revisión
auth; permite compartir source Prisma/TypeScript con el bootstrap NodeNext compilado.

Docker interno no publicó el puerto de app. La prueba usa un relay efímero del runner
vinculado exclusivamente a loopback y dirigido a la IP del contenedor propio.
App/DB conservan red interna, cap-drop ALL, no-new-privileges y límites.
No hay puertos DB publicados, host network, socket Docker dentro ni red externa runtime.
La fixture HTTPS local sirve únicamente para verificar Secure; no es deployment/TLS
productivo. Certificado y clave efímeros quedan fuera del montaje de la aplicación.
